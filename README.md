# ClipFlow

A native macOS clipboard manager where text you copied and text *inside*
screenshots you copied land in the same search index. Type `connection refused`
and you get both the error message you copied and the screenshot of it.

There is no separate image-search mode, and no toggle. Screenshots are OCR'd on
device with Apple's Vision framework as they arrive, and the extracted text goes
into the same FTS5 index as everything else. Maccy, the closest comparable app,
has no OCR at all.

Menu bar only. SwiftUI, GRDB/SQLite, two dependencies total.

## Install

Requires macOS 15 or later. Building needs Xcode or the Command Line Tools —
the build itself only calls `swift build` and `codesign`, so Command Line Tools
is likely enough, but that has not been tested here.

```
git clone https://github.com/jayyy044/clipflow.git
cd clipflow
make install
```

That builds a release binary, assembles `ClipFlow.app`, signs it, copies it to
`/Applications`, and launches it. `make uninstall` removes it. `make run` runs
it out of `dist/` without installing.

An app you build yourself is never quarantined, so Gatekeeper never gets
involved — no "unidentified developer" dialog, no right-click-Open dance, no
notarisation. This is the whole distribution story: there is no signed release
build, and none is needed to run it.

The Makefile signs with an Apple Development certificate if it finds one, and
falls back to an ad-hoc signature if not. Ad-hoc works, with one consequence:
macOS keys the Accessibility grant on the signing identity, so an ad-hoc build
loses the grant on every rebuild and you have to re-approve pasting. See
DECISIONS D-11.

ClipFlow registers itself for launch at login on first run. macOS may park that
request pending your approval in System Settings > General > Login Items.

## Usage

`Ctrl+Cmd+V` opens the panel. Left-clicking the menu bar icon does the same.

The search field is focused on open, so just type. The panel does not steal
focus from the app you were in, which is what makes pasting back into it work.

| Key | Action |
| --- | --- |
| `Enter` | Copy the selected item and close. With nothing selected, copies the top result. |
| Click a row | Same as Enter |
| `Option+Enter` | Paste into the app you were in |
| `Option+Shift+Enter` | Paste as plain text |
| `Up` / `Down` | Move through the list |
| `Option+Delete` | Delete the selected item |
| `Esc` | Close |

Delete needs Option because focus lives in the search field, where a bare
Delete has to keep editing the query.

Right-clicking a row gives the same actions as a menu: Copy, Paste, Paste as
Plain Text, Delete. Right-clicking the menu bar icon gives Clear History (with
a confirmation) and Quit.

Pasting presses Cmd+V in the other app for you, which macOS only permits with
Accessibility permission. Without it, ClipFlow copies instead and says so once;
"Enable Pasting…" then stays in the menu bar menu. Pasting is also skipped when
macOS secure input is active — typically a focused password field — because the
synthetic keystroke would be silently discarded. In both cases the item is on
your clipboard and Cmd+V yourself works.

`Option+Shift+Enter` currently does the same thing as `Option+Enter`: text items
store plain text only, so there is no formatting to strip.

## Privacy

No network calls. Not telemetry, not update checks, not an OCR API — the app
makes no outbound connections of any kind.

OCR runs on device through Apple's Vision framework. Nothing leaves the machine.

Everything is stored under `~/Library/Application Support/ClipFlow/`:
`clipflow.sqlite` for items and the search index, `images.noindex/` for image
payloads and thumbnails. The `.noindex` suffix keeps Spotlight from indexing
your clipboard screenshots into system-wide search. Nothing is encrypted beyond
whatever FileVault gives you.

Content marked `org.nspasteboard.ConcealedType`, `TransientType`, or
`AutoGeneratedType` is never recorded, which covers 1Password, Bitwarden, and
Apple Passwords.

**That guarantee stops where the marking stops.** Plenty of ways to move a
secret through the clipboard set no concealed type at all — `pass`, `gpg`,
`echo $TOKEN | pbcopy`, `kubectl get secret`, several browser autofill paths. If
the source does not mark it, ClipFlow stores it like any other text. There is no
app exclusion list yet. See DECISIONS S-3.

## Limitations

- **Dense tables and charts OCR badly.** On a dense tabular screenshot, Vision
  returns a small fraction of the visible text, and chart axis labels come back
  as noise. Terminals, code, prose and documentation read fine. Measured, not
  guessed — DECISIONS D-10.
- **History keeps the newest 100 items.** Older ones are evicted permanently.
  Delete and Clear History are also permanent — no undo, no trash.
- **No rich text.** RTF is not stored, so formatting is lost on the round trip.
  HTML representations are dropped too, so pasting a web selection into Notion
  or Slack will not match a direct paste.
- **No sync.** Single machine, by design.
- **Not built yet:** pinning, URL actions, an app exclusion list, pause capture,
  a Settings window. The hotkey and the retention limit are constants in source,
  not preferences.
- **Skipped on capture:** text over 1 MB, images over 32 MB, and images over
  8000 px on an edge are not OCR'd. A failed OCR is never retried.
- **English only** for OCR — the recognition language is pinned, because
  automatic detection is a coin flip on a terminal screenshot.

## Building

```
make bundle      # build dist/ClipFlow.app
make run         # build and run from dist/
make debug       # unbundled binary, for iterating
make clean
```

`make debug` reads a different UserDefaults domain than the bundle, so the
hotkey preference does not carry across.
