# ClipFlow: Product Requirements Document

**Working name:** ClipFlow (rename freely)
**Platform:** macOS 15 Sequoia or later
**Status:** Draft v1
**Owner:** Maanas

> Draft v1, verbatim. Decisions that override this document live in
> [DECISIONS.md](DECISIONS.md) — read that first. Notably: build strategy is
> Path A, not Path B (D-1), and the window layer is `NSStatusItem` + `NSPanel`,
> not `MenuBarExtra` (D-2).

---

## 1. Problem Statement

macOS holds exactly one clipboard item. macOS 26 Tahoe added a Spotlight clipboard history, but it is text only with a 7 day retention limit and no pinning.

Existing third party managers each fail on at least one axis:

| App | Fails because |
| --- | --- |
| Maccy | No OCR on images, no URL actions |
| PasteBar | Tauri webview, heavy, forces collections/boards |
| CopyQ | Qt, non-native feel, scripting complexity nobody uses |
| Clipory / Pastery | Paid, and Pastery uses a card timeline instead of a flat list |

ClipFlow targets the gap: a native, minimal, flat-list clipboard manager where **text and the text inside images are searchable through a single unified query**.

---

## 2. Goals

**G1.** Never lose a copied item.
**G2.** Retrieve any item in under three seconds from keypress to paste.
**G3.** Find a screenshot by typing words that appear *inside* it.
**G4.** Stay invisible: negligible RAM and CPU when idle.
**G5.** Never record credentials.

---

## 3. Non-Goals (v1)

These are deliberately excluded. Do not implement them, do not leave hooks for them.

| Excluded | Reason |
| --- | --- |
| Collections, tabs, boards, folders | Filing is friction at the exact moment the user wants speed. Flat list plus search solves retrieval. |
| Tags and notes | Same as above, plus vocabulary maintenance. |
| Cloud or iCloud sync | Single machine scope. Adds conflict resolution and an encryption story for no v1 benefit. |
| Snippet library / text expansion | Different tool. Espanso does this better. |
| Scripting or plugin system | Nobody writes the scripts. |
| Passcode or PIN lock on the UI | Locks the window, not the data. FileVault is the real control. |
| Syntax highlighting | Cosmetic, changes nothing about what gets pasted. |
| iOS companion app | Out of scope. |

---

## 4. Target User

A developer who copies constantly: error messages, stack traces, commit hashes, URLs, config lines, and screenshots of documentation and dashboards. Keyboard first. Will not tolerate a laggy menu bar app.

## 5. Functional Requirements

### 5.1 Capture

**FR-1.1** Poll `NSPasteboard.general.changeCount` at 500 ms. Capture only when the count changes.

**FR-1.2** Capture these types, in priority order when multiple representations exist:
1. `public.png` / `public.tiff` -> image item
2. `public.file-url` -> file item (store path, not contents)
3. `public.rtf` -> text item (store both RTF data and plain string)
4. `public.utf8-plain-text` -> text item

**FR-1.3** Deduplicate. If the incoming content hash matches the most recent item, update its `last_used_at` and do not insert a new row.

**FR-1.4** Skip capture when the pasteboard declares any of:
- `org.nspasteboard.ConcealedType` (set by 1Password, Bitwarden, Apple Passwords)
- `org.nspasteboard.TransientType`
- `org.nspasteboard.AutoGeneratedType`

**FR-1.5** Skip capture when the frontmost app's bundle identifier is on the user's exclusion list.

**FR-1.6** Record the source app bundle ID and display name on every item.

### 5.2 Storage

**FR-2.1** SQLite in `~/Library/Application Support/ClipFlow/`. Use GRDB.swift.

**FR-2.2** Images are written to disk as files under `.../ClipFlow/images/<uuid>.png`. The database stores the relative path only. Never store image blobs in SQLite.

**FR-2.3** Schema:

```sql
CREATE TABLE items (
  id              INTEGER PRIMARY KEY,
  kind            TEXT NOT NULL,          -- 'text' | 'image' | 'file'
  content         TEXT,                   -- plain text payload; NULL for image
  rtf_data        BLOB,                   -- optional rich representation
  image_path      TEXT,                   -- relative path; NULL for text
  preview         TEXT NOT NULL,          -- display string, truncated to 200 chars
  source_bundle_id TEXT,
  source_app_name TEXT,
  pinned          INTEGER NOT NULL DEFAULT 0,
  pin_slot        INTEGER,                -- stable 1..9 for pinned shortcuts
  copied_at       INTEGER NOT NULL,       -- unix epoch seconds
  last_used_at    INTEGER,
  content_hash    TEXT NOT NULL,
  ocr_status      TEXT NOT NULL DEFAULT 'na',  -- 'na'|'pending'|'done'|'failed'
  ocr_text        TEXT,
  detected_urls   TEXT,                   -- JSON array
  detected_phones TEXT                    -- JSON array
);

CREATE INDEX idx_items_copied_at ON items(copied_at DESC);
CREATE INDEX idx_items_hash      ON items(content_hash);
CREATE INDEX idx_items_ocr       ON items(ocr_status) WHERE ocr_status = 'pending';

CREATE VIRTUAL TABLE items_fts USING fts5(
  content,
  ocr_text,
  content='items',
  content_rowid='id',
  tokenize='unicode61 remove_diacritics 2'
);
```

**FR-2.4** Keep FTS in sync with `items` via SQLite triggers on insert, update, and delete.

**FR-2.5** Retention: keep the newest N unpinned items, default N = 1000, user configurable. Pinned items are never evicted. On eviction, delete the orphaned image file from disk.

### 5.3 Search

**FR-3.1** A single search field queries `items_fts` across both `content` and `ocr_text`. There is no separate image search mode. This is the core differentiator.

**FR-3.2** Support prefix matching so partial words match (`err` matches `error`).

**FR-3.3** Rank by BM25, then boost pinned items to the top, then break ties by `copied_at` descending.

**FR-3.4** Empty query shows the flat reverse chronological list with pinned items above it.

**FR-3.5** Search runs on every keystroke, debounced at 40 ms.

### 5.4 OCR

**FR-4.1** When an image item is inserted, enqueue it with `ocr_status = 'pending'`.

**FR-4.2** A background serial queue processes pending items using Vision `VNRecognizeTextRequest` with `recognitionLevel = .accurate` and `usesLanguageCorrection = true`.

**FR-4.3** On success, write the joined recognized strings to `ocr_text`, set `ocr_status = 'done'`, and update the FTS index. On failure, set `'failed'` and do not retry.

**FR-4.4** OCR must never block the UI or the capture poller.

**FR-4.5** Process pending OCR work on launch so a queue interrupted by quitting resumes.

**FR-4.6** Skip OCR for images above a size threshold (default 8000 px on either edge) to avoid pathological cases.

### 5.5 Detection and Actions

**FR-5.1** On text insert, run `NSDataDetector` with `.link` and `.phoneNumber`. Store results as JSON arrays.

**FR-5.2** Item actions:

| Action | Shortcut | Behavior |
| --- | --- | --- |
| Copy to clipboard | `Enter` | Writes item to pasteboard, closes window |
| Paste into frontmost app | `Option + Enter` | Writes, then synthesizes Cmd+V |
| Paste as plain text | `Option + Shift + Enter` | Strips RTF, writes plain string, synthesizes Cmd+V |
| Paste item N directly | `Option + 1..9` | Skips the window entirely |
| Pin / unpin | `Option + P` | Assigns or frees a stable `pin_slot` |
| Delete item | `Option + Delete` | Removes row and any orphaned image file |
| Open URL | `Cmd + O` | Only enabled when `detected_urls` is non-empty |

**FR-5.3** Open URL uses `NSWorkspace.shared.open(urls:withApplicationAt:configuration:)` targeting a user-configured browser, defaulting to the system default browser. If the item contains multiple URLs, open the first.

**FR-5.4** Paste actions require Accessibility permission. If not granted, fall back to copy-only and surface a one time prompt explaining why.

### 5.6 User Interface

**FR-6.1** `MenuBarExtra` with a monochrome template icon. No Dock icon (`LSUIElement = true`).

**FR-6.2** Global hotkey defaults to `Cmd + Shift + C`, rebindable, using the `KeyboardShortcuts` package.

**FR-6.3** Window layout, top to bottom: search field, pinned section (only when pinned items exist), flat history list.

**FR-6.4** Row contents: source app icon, preview text or image thumbnail, relative timestamp. A link glyph when URLs were detected. A small indicator on image rows whose `ocr_status` is `pending`.

**FR-6.5** Full keyboard navigation. Arrow keys move selection, `Esc` closes, focus lands in the search field on open.

**FR-6.6** Follows system light and dark appearance. No custom theming.

**FR-6.7** Image rows render a downscaled thumbnail. Never load full resolution images into the list.

### 5.7 Privacy and Settings

**FR-7.1** Everything stays local. Zero network calls of any kind, including analytics and update checks in v1.

**FR-7.2** App exclusion list, managed in Settings by picking apps.

**FR-7.3** "Ignore next copy": a modifier click on the menu bar icon suppresses the very next capture.

**FR-7.4** "Pause capture": toggles the poller off, with a visibly dimmed menu bar icon.

**FR-7.5** Clear unpinned history, and clear everything including pinned, as separate destructive actions with confirmation.

**FR-7.6** Optional: clear all unpinned history when the screen locks.

**FR-7.7** Launch at login via `SMAppService`.

## 6. Non-Functional Requirements

These are acceptance thresholds, not aspirations. Measure them.

| Metric | Budget |
| --- | --- |
| Idle resident memory | < 60 MB |
| Idle CPU | < 0.1% average |
| Cold launch to menu bar ready | < 500 ms |
| Hotkey to window visible | < 100 ms |
| Search latency, 10k items | < 50 ms |
| OCR per screenshot (Apple Silicon) | < 1.5 s, off main thread |
| Database size, 1000 text items | < 5 MB excluding images |

**NFR-1** Native Swift and SwiftUI only. No Electron, no Tauri, no embedded webview. This is a hard constraint and the reason several existing apps were rejected.

**NFR-2** Universal binary, Apple Silicon and Intel.

**NFR-3** No third party dependencies beyond GRDB.swift and KeyboardShortcuts.

## 7. Technical Architecture

### 7.1 Stack

- **Language:** Swift 6
- **UI:** SwiftUI, `MenuBarExtra`
- **Persistence:** SQLite via GRDB.swift, FTS5 for search
- **OCR:** Vision (`VNRecognizeTextRequest`), first party, on device
- **Detection:** `NSDataDetector`
- **Hotkeys:** KeyboardShortcuts (Sindre Sorhus)
- **Paste injection:** `CGEvent` keystroke synthesis

### 7.2 Module Breakdown

```
ClipFlow/
├── App/
│   ├── ClipFlowApp.swift          # @main, MenuBarExtra, lifecycle
│   └── AppState.swift             # observable root state
├── Capture/
│   ├── PasteboardMonitor.swift    # changeCount polling loop
│   ├── PasteboardReader.swift     # type priority resolution
│   └── ExclusionRules.swift       # concealed types + app blocklist
├── Storage/
│   ├── Database.swift             # GRDB setup, migrations
│   ├── Item.swift                 # record type
│   ├── ItemRepository.swift       # insert, query, evict
│   └── Migrations/
├── Search/
│   └── SearchService.swift        # FTS5 query building, ranking
├── OCR/
│   ├── OCRQueue.swift             # serial background queue
│   └── VisionRecognizer.swift     # VNRecognizeTextRequest wrapper
├── Detection/
│   └── DataDetector.swift         # URLs, phone numbers
├── Actions/
│   ├── Paster.swift               # CGEvent Cmd+V synthesis
│   └── URLOpener.swift            # NSWorkspace browser targeting
├── UI/
│   ├── HistoryWindow.swift
│   ├── ItemRow.swift
│   ├── SearchField.swift
│   └── Settings/
└── Permissions/
    └── AccessibilityGate.swift
```

### 7.3 Data Flow

```
Timer 500ms
   -> changeCount differs?
      -> ExclusionRules.shouldCapture()   [concealed types, app blocklist, paused]
         -> PasteboardReader.read()       [type priority]
            -> hash, dedupe check
               -> ItemRepository.insert()
                  -> FTS trigger fires
                  -> if image: OCRQueue.enqueue()
                       -> VisionRecognizer (background)
                          -> UPDATE ocr_text, ocr_status
                             -> FTS trigger fires again
```

Both text and OCR output land in the same FTS table. One query searches both.

## 8. Known Hard Problems

**HP-1: There is no clipboard change notification on macOS.** No observer, no callback. Polling `changeCount` is the only approach and is what every clipboard manager does. Do not spend time looking for an event based API.

**HP-2: Pasting into another app is the hardest part.** Writing to the pasteboard is trivial. Making the frontmost app paste requires synthesizing Cmd+V via `CGEvent`, which requires Accessibility permission. Expect timing issues: the target app needs a brief moment after the ClipFlow window closes before it will accept the synthetic keystroke.

**HP-3: Apps write multiple representations.** Copying from Word puts RTF, HTML, plain text, and sometimes an image on the pasteboard simultaneously. The priority order in FR-1.2 must be applied deterministically or the same copy will be classified differently across runs.

**HP-4: Hotkeys that produce characters get blocked in password fields.** If a chord like `Option+C` emits a character, macOS security may suppress it in secure input contexts. Default to a chord that does not emit one.

**HP-5: Image memory.** Loading full resolution screenshots into a list view will blow the RAM budget immediately. Generate and cache thumbnails on insert.

**HP-6: Secure input mode.** When any app has secure input enabled, global hotkeys may not fire. Detect and surface this rather than appearing broken.

## 9. Build Phases

Each phase ends in something runnable. Do not start the next phase until the acceptance criteria pass.

### Phase 0: Skeleton
Menu bar app with `LSUIElement`, empty window, launches and quits cleanly.
**Accept:** icon appears, click opens an empty window, no Dock icon.

### Phase 1: Capture and Store Text
Polling monitor, GRDB setup, schema migration, insert on change, dedupe.
**Accept:** copy three distinct strings, all three are rows in the database. Copy the same string twice, still one row.

### Phase 2: Flat List UI
Reverse chronological list, source app icon, relative timestamps, arrow key navigation.
**Accept:** copied items appear in the list within one second, newest first.

### Phase 3: Search
FTS5 table, sync triggers, debounced query, BM25 ranking.
**Accept:** typing filters to matching items in under 50 ms with 1000 rows seeded.

### Phase 4: Copy and Paste Actions
Enter to copy, Option+Enter to paste, Option+Shift+Enter for plain text, Accessibility permission flow.
**Accept:** Option+Enter pastes into TextEdit. Option+Shift+Enter pastes styled text from a webpage as unstyled.

### Phase 5: Global Hotkey
KeyboardShortcuts integration, rebindable, Option+1..9 direct paste.
**Accept:** Cmd+Shift+C opens the window from any app. Option+3 pastes the third item without opening the window.

### Phase 6: Images
Image capture, disk storage, thumbnail generation and caching, image rows.
**Accept:** copy a screenshot, it appears as a thumbnail, pastes correctly into Preview. Idle RAM still under 60 MB with 50 images stored.

### Phase 7: OCR (the differentiator)
Background queue, Vision integration, write into `ocr_text`, FTS reindex, resume pending on launch.
**Accept:** copy a screenshot of an error message, wait two seconds, type a word from that error into search, the screenshot is returned.

### Phase 8: Detection and URL Actions
`NSDataDetector`, link glyph on rows, Cmd+O opens in configured browser.
**Accept:** copy a URL, Cmd+O opens it in Chrome. Copy a phone number, it is detected and stored.

### Phase 9: Privacy and Settings
Concealed type handling, app exclusion list, ignore next copy, pause, clear actions, retention eviction, launch at login.
**Accept:** copying a password from a password manager produces no row. An excluded app produces no rows. Retention caps the table at N.

### Phase 10: Polish
Onboarding for permissions, empty states, performance pass against every NFR budget.
**Accept:** all Section 6 budgets measured and met.

## 10. Build Strategy Decision

> Superseded by [DECISIONS.md](DECISIONS.md) D-1: **Path A**. Maccy is
> SwiftData + Fuse fuzzy search, so FTS5 over `content` + `ocr_text` is
> unreachable without rewriting the storage and search layers — the two phases
> Path B was supposed to skip.

Two viable paths. Decide before Phase 0.

**Path A: Greenfield.** Build from scratch per this document. Full control, clean architecture, no inherited decisions. Costs roughly two to three extra weeks re-solving polling, permissions, hotkeys, and paste injection, all of which are solved problems.

**Path B: Fork Maccy.** Maccy is MIT licensed, native Swift, and already implements Phases 0 through 6 and 9 to a production standard. The work reduces to Phase 7 (OCR) and Phase 8 (URL actions) against a codebase that already handles the edge cases in Section 8.

Path B ships the feature that actually matters far sooner and provides well written production Swift to learn from. Path A teaches more but has a much higher chance of stalling.

Recommendation: **Path B**, unless learning macOS development from first principles is itself a primary goal of this project.

## 11. Open Questions

> Answered in [DECISIONS.md](DECISIONS.md) D-5.

1. Should pinned items be excluded from search results, or ranked above them? (Spec currently says ranked above.)
2. Should file items store a path reference only, or copy the file into app storage? (Spec says reference only. Reference breaks if the file moves.)
3. Should OCR run on images copied from an excluded app if the image itself was not excluded? (Spec implies no capture at all, so the question does not arise.)
4. What is the right retention default? 1000 is a guess. Instrument actual usage before hardcoding.
5. Is a browser picker in Settings worth it, or should Cmd+O always use the system default browser?

## 12. Success Criteria

ClipFlow v1 is done when it has fully replaced Maccy in daily use for two consecutive weeks, and:

- Every Section 6 budget is met
- A screenshot copied a week ago is findable by a word inside it
- No credential has ever appeared in the history
- The app has not needed to be manually restarted
